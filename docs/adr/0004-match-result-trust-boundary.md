# ADR-0004: 試合結果の信頼境界をサーバー側に置く

- 状態: 採用
- 日付: 2026-08-11
- 対象: Match Pool、Gateway、D1 レーティング

## 背景

Client が `playerAId`、`playerBId`、勝敗を自由に確定できると、別人のレーティングを
変更したり、成立していない試合を登録したりできます。結果再送や同時確定では ELO の
二重反映も防ぐ必要があります。

## 決定

結果 API は `matchId`、`resultId`、A 側の `result` だけを受け付けます。Gateway の
認可 Hook が許可した処理だけを進め、参加者 ID は成立済み Match Pool のチケットから
復元します。D1 では試合行、2 人の参加者履歴、2 人の Rating 更新を version 条件付き
の batch で確定します。`matchId` または `resultId` が既存なら再計算せず、`applied:
false` を返します。

## 代替案

- Client から参加者 ID を受け取る: なりすましを許すため不採用。
- 結果をキューへ積み後で更新する: 確定済み結果と現在値の可視性が分かれ、v0.1.0 の
  1 回確定契約を満たしにくいため不採用。
- プレイヤーごとに個別更新する: 片方だけ更新済みになるため不採用。

## 結果

結果確定の権限と参加者の正本をサーバー側へ閉じ込め、同じ結果の再送と version 競合を
安全に扱えます。ゲームの勝敗を判定するサーバー Hook 自体は利用者が実装します。
