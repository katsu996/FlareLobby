# ADR-0002: `revision` と再開トークンで再接続する

- 状態: 採用
- 日付: 2026-08-11
- 対象: Room WebSocket、Client SDK

## 背景

ブラウザの WebSocket は一時的に切断されます。切断を即時退出として扱うと参加者の
準備状態やホストが失われ、逆に受信イベントを無条件に適用すると欠落・逆順・重複で
クライアントの状態が壊れます。

## 決定

Room の状態変更ごとに `revision` を増やし、イベントには適用後の値を付けます。
Client は次の版だけを適用し、重複は破棄、欠落や逆順は再同期へ切り替えます。Room は
有界イベント履歴を保存し、接続時に主体・Room・役割・参加者・nonce・期限へ束縛した
再開トークンを subprotocol で受け取ります。履歴が不足した場合は完全 Snapshot を
返します。

通信切断では参加者を切断猶予中として保持し、明示的な `leave()`/`kick()`/`close()`
だけが再開セッションを無効化します。

## 代替案

- 最新 Snapshot だけを毎回送る: 簡単だが、切断中の更新を効率よく復元できないため不採用。
- クライアント側の時刻や `playerId` だけで再接続する: なりすましと古い接続の再利用を許すため不採用。
- 無制限のイベント履歴: SQLite と再接続処理の容量が無制限になるため不採用。

## 結果

切断中の状態を保持しながら、履歴がある場合は差分、ない場合は完全 Snapshot へ
安全にフォールバックできます。再接続回数、切断猶予、履歴件数、トークン TTL は
設定値として制限します。
