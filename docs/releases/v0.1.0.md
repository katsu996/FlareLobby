# FlareLobby v0.1.0 Release Note

FlareLobby v0.1.0 は、Cloudflare Workers と Durable Objects でゲーム向けロビー、
招待ルーム、1 対 1 ランクマッチングを構築するための最小実用版です。

## 公開対象 package

| package                  | 役割                                                |
| ------------------------ | --------------------------------------------------- |
| `@flarelobby/core`       | 公開型、プロトコル、候補探索、ELO                   |
| `@flarelobby/cloudflare` | Gateway Worker、Durable Objects、D1、認証・認可境界 |
| `@flarelobby/client`     | ブラウザ向け HTTP/WebSocket Client SDK              |
| `@flarelobby/testing`    | 仮想時計、固定乱数、決定論的シミュレーター          |

すべて `0.1.0`、ES Modules、MIT License、public scoped package として構成しています。

## 主な機能

- 招待または公開一覧から参加できるカスタムルーム
- 準備、チーム選択、ホスト操作、退出、切断猶予と状態復元
- 1 対 1 ランクキュー、待機時間に応じた検索幅、取消と期限切れ
- 信頼されたサーバー処理による試合結果登録と冪等な ELO 更新
- Client SDK、自動再接続、決定論的シミュレーター
- 招待ルームとランク戦を確認できる最小じゃんけんゲーム

詳細な変更は [CHANGELOG](../../CHANGELOG.md)、導入手順は
[導入とローカルサンプル](../getting-started.md)、全公開 API は
[API リファレンス](../api-reference.md) を参照してください。

## 既知の制限

- 対応する組み込みランクマッチングは 1 対 1、レーティングは ELO のみです。
- 公開ルーム一覧は D1 への非同期投影で、一時的に古い場合があります。最終的な
  定員と参加可否は Room Durable Object が判定します。
- ローカルサンプルの `x-demo-player` 認証は説明用です。本番環境では利用者側の
  認証サービスと認可 Hook が必要です。
- Cloudflare の D1、Durable Objects、Secret、任意の Analytics Engine は利用者の
  アカウントと環境ごとに作成・設定する必要があります。
- v0.1.0 の API は初回公開版です。将来の互換性方針は Semantic Versioning に従い、
  破壊的変更は Changeset と移行手順で明示します。

## 対象外

- 高頻度で動く権威ゲームサーバー、物理演算、ゲーム本体の同期
- パーティーマッチング、2 対 2 以上のチームマッチング、高度なロール制約
- ELO 以外の組み込みレーティング
- ボイスチャット、映像配信、WebRTC 通信本体、汎用的なチート対策
- 管理画面、複数リージョンをまたぐ高度なキュー統合、他クラウド向け実行基盤

## 公開前検証

クリーンな checkout で Node.js `24.19.0` と pnpm `11.21.0` を用意し、次を実行します。

```sh
pnpm install --frozen-lockfile
pnpm release:check
```

`release:check` は build、型検査、単体テスト、Workers 統合テスト、文書/API、
ES Modules、Workers 型、4 package の npm publish dry-run、サンプル Worker の
`wrangler deploy --dry-run` を順番に実行します。dry-run は npm registry や
Cloudflare へ成果物を公開しません。

2026-08-11 の公開前監査では 4 package 名が npm registry で未公開であることを
確認しました。実際の公開前には、所有者が `@flarelobby` scope の公開権限と npm
認証を改めて確認する必要があります。

2026-08-12 に `pnpm release:check` を実行し、次の結果を確認しました。

## 許容した診断と理由

| 診断                                                                         | 判断                                                                                                                                                                                                       |
| ---------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Codex host の mise が個人設定内の `npm:@katsu996/md2html` を解決できない警告 | リポジトリ外の `~/.config/mise/config.toml` に由来します。固定済み Node.js、pnpm、Wrangler と全検証の終了コードへ影響せず、クリーン CI には存在しません。                                                  |
| Codex の管理 Proxy を Wrangler が検出した警告                                | 実行環境の通信経路の通知です。telemetry を無効にした deploy dry-run は upload せず、Bundle と全 Binding の検証に成功しました。                                                                             |
| Wrangler 4.120.1 の更新通知                                                  | 4.120.1 と依存 Miniflare は公開後 24 時間未満で CI の minimum release age policy に拒否されたため、policy 例外を追加せず検証済みの 4.120.0 を維持しました。安全期間経過後の更新は別 Changeset で扱います。 |
| Workers 統合テスト中の満員・権限・状態・パスワード拒否に関する診断ログ       | 失敗経路を検証するテストが意図的に発生させた安定エラーです。対応する assertion を含む 95/95 の Cloudflare package integration tests が成功しました。                                                       |

実行していません。これらは所有者の明示的な最終承認と対象環境の認証確認後にのみ
実行します。
